## P2 — Before opening operator admission or production deployment

- [ ] **Protect first initialization.** `Initialize` accepts any signer and stores that signer as protocol authority; no expected initializer or upgrade-authority check is present. Before a fresh deployment, either enforce the intended bootstrap authority or demonstrate a deployment procedure that prevents a third party claiming the singleton config first. Add a regression test for the chosen protection.
- [ ] **Resolve or explicitly constrain ticket grinding and signer exclusion.** `state/ticket.rs` still hashes the aggregate signature into ticket eligibility, allowing eligible signers to re-sign for another lottery result. The existing second-pass report discusses requester-influenced committee selection and exclusion attacks. Commission a current threat-model review across gateway, nodes and verifier; regression-test the chosen mitigation before admitting untrusted operators. The report's numerical attack estimates were not independently reproduced here.
- [ ] **Validate availability penalties against actual ceremony behavior.** `EpochState::weight` still zeroes payout below the sampled availability floor. Test expected registry sizes and honest partial-signature inclusion behavior, choose an acceptable false-penalty rate, and document sample targets and inactivity policy. The existing report's statistical estimates require validation against the current node/gateway implementation.
- [ ] **Make reward-credit races recoverable.** `credit_epoch_rewards` fails the entire batch if a slot is already credited or has zero weight. Verify keeper refresh/retry behavior under concurrent crankers, or make already-credited entries safely skippable. Add a concurrency regression test.
- [ ] **Confirm accounting and overlap policies.** Document that subscription revenue is booked when swept, and that prior registry versions can remain valid during transition overlap. Test which epoch gets revenue and what happens to removed/frozen nodes, zero-weight epochs, forfeitures and residuals.
- [ ] **Test deployment and account-layout migration.** Historical reviews note layout changes in `Registry` and `EpochState`. Verify actual deployed layouts before upgrades; choose fresh deployment or a tested migration. The migration script is currently a placeholder. Record upgrade/administrative custody, initialization values, mint identity and rollback procedure.
- [ ] **Run external security review and local integration acceptance.** Cover account substitution/signers, remaining-account validation, signature parsing and domain separation, replay boundaries, treasury liabilities, deposit isolation and slashing. Exercise the real gateway/node/consumer flow with disposable local keys and explicit loopback RPCs. This review did not establish full-stack interoperability or production safety.
