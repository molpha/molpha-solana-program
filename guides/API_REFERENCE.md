# API reference

The IDL generated by `anchor build -p molpha` (`target/idl/molpha.json`) is the machine-readable
interface. This page is an index into it. For how the pieces interact, see
[Architecture](ARCHITECTURE.md).

## Instructions

Entrypoints are declared in `programs/molpha/src/lib.rs`.

| Area          | Instructions                                                                                    | Who can call                                      |
| ------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Configuration | `initialize`                                                                                    | First caller, who becomes the authority           |
| Configuration | `update_config`, `update_registry_policy`                                                       | Authority                                         |
| Nodes         | `register_node`                                                                                 | Node owner and authority, both signing            |
| Nodes         | `update_node_endpoint`                                                                          | Node owner                                        |
| Nodes         | `deactivate_node`                                                                               | Node owner or authority                           |
| Nodes         | `reinstate_node`                                                                                | Anyone after the freeze window; authority earlier |
| Node funds    | `claim_node_rewards`, `withdraw_node_deposit`                                                   | Node owner                                        |
| Plans         | `add_plan`, `update_plan`                                                                       | Authority                                         |
| Subscriptions | `subscribe`, `extend_subscription`                                                              | Subscriber                                        |
| Delegates     | `add_delegate`, `remove_delegate`                                                               | Subscription owner                                |
| Gateways      | `register_gateway`, `deactivate_gateway`                                                        | Authority                                         |
| Publication   | `submit_attestation`                                                                            | Anyone holding a valid attestation                |
| Epochs        | `submit_ticket`, `close_ticket_marker`, `finalize_epoch`, `credit_epoch_rewards`, `close_epoch` | Anyone                                            |
| Treasury      | `sweep_treasury_revenue`                                                                        | Anyone                                            |
| Treasury      | `withdraw_protocol_reserve`                                                                     | Authority                                         |
| Evidence      | `slash_offence`                                                                                 | Anyone                                            |

Signature primitives come from the separately versioned
[`molpha-verifier`](https://github.com/molpha/molpha-verifier) crate. There is no verify-only
instruction: a consumer reads the `Feed` account that `submit_attestation` wrote.

## `Feed` account

Defined in `programs/molpha/src/state/feed.rs`. The PDA seeds are `molpha_feed`, the 32-byte source
ID, the one-byte quorum and the submitter's public key.

| Field                 | Meaning                                                                    |
| --------------------- | -------------------------------------------------------------------------- |
| `source_id`           | Application source identity, 32 bytes                                      |
| `value`               | Signed 32-byte value, or the Keccak-256 hash of a longer one               |
| `value_kind`          | `Value` or `Hash`. A hashed preimage travels in the submitting instruction |
| `submitter`           | Submitter public key; part of the PDA identity                             |
| `timestamp`           | Unix milliseconds, strictly increasing across updates                      |
| `signatures_required` | Quorum, `u8`                                                               |
| `signers_bitmap`      | 32-byte signer bitmap                                                      |
| `registry_version`    | `u32` registry snapshot version                                            |
| `bump`                | Canonical PDA bump                                                         |

The program does not assign decimals or a confidence interval to `value`; its encoding is agreed
per source. Epochs and chain clocks use seconds, so divide a feed timestamp by 1,000 before
comparing it with them.
